FRONT-END DESIGN ENGINEERING(01)
SPRINT 04 – INTEGRAÇÃO COM BACKEND E CONSUMO DE API
A SPRINT 04 marca a etapa final de desenvolvimento do projeto, consolidando todo o trabalho realizado nas fases anteriores e evoluindo a solução para
um nível profissional de entrega. Nesta etapa, a aplicação deverá ser concluída utilizando React + Vite + TypeScript, mantendo a arquitetura modular e o
padrão SPA (Single Page Application) desenvolvidos na SPRINT 03.
Além da continuidade estrutural e visual, a SPRINT 04 tem como principal objetivo integrar funcionalidades reais ao projeto por meio de consumo de
APIs, conectando o FRONT-END com os serviços desenvolvidos na disciplina de Domain Driven Design Using Java. Essa integração deve ser feita por
meio de requisições HTTP aos endpoints criados pelo grupo, garantindo comunicação entre cliente (Front-End) e servidor (Back-End).
Tecnologias obrigatórias nesta etapa: REACT, VITE e TYPESCRIPT.
Sprint 04
FRONT-END DESIGN ENGINEERING(02)
OBJETIVO
Desenvolver uma aplicação Web completa utilizando React + Vite + TypeScript, aplicando boas práticas de Front-End Design Engineering, com foco em:
• Componentização e arquitetura modular, visando escalabilidade e facilidade de manutenção;
• Integração com APIs REST, consumindo endpoints desenvolvidos na disciplina de Domain Driven Design Using Java, garantindo comunicação consistente entre frontend e
backend;
• Abordagem Single Page Application (SPA), proporcionando navegação fluida e rápida sem recarregamento total da página;
• Padrões de projeto modernos, aplicando recursos do ecossistema React como hooks (useState, useEffect, useContext) e organização eficiente de componentes;
• Tipagem estática com TypeScript, garantindo maior confiabilidade e redução de erros durante o desenvolvimento;
• Experiência do usuário coesa e responsiva, com design acessível e alinhado às boas práticas de usabilidade;
• Estilização com Tailwind CSS, assegurando consistência visual e produtividade no desenvolvimento da interface;
• Responsividade completa, garantindo adaptação correta da interface para diferentes dispositivos e tamanhos de tela;
• Qualidade técnica do código, seguindo padrões de clean code e organização de pastas;
• Versionamento colaborativo com GitHub, registrando o histórico de desenvolvimento e garantindo integração contínua entre os membros da equipe;
• Documentação técnica clara, por meio de um arquivo README.md completo, que explique instalação, execução e estrutura do projeto;
• Deploy profissional na Vercel, disponibilizando a aplicação online para avaliação e acesso público.

ALGUMAS REGRAS (01/04)
1. FRAMEWORK
O projeto final deverá ser estruturado utilizando REACT + VITE + TYPESCRIPT, obrigatoriamente, onde o roteamento de páginas e outras adaptações necessárias serão implementados.
2. RESPONSIVIDADE
A aplicação deve ser totalmente responsiva utilizando exclusivamente Tailwind CSS, garantindo funcionamento adequado em diferentes resoluções, incluindo Mobile (até 480px),
Tablet (768px) e Desktop (992px ou superior), preservando a integridade do layout sem quebras de design em nenhuma dimensão de tela.
3. DEPLOY DO PROJETO
Além disso é fundamental realizar o deploy do projeto na plataforma VERCEL. A URL aqui criada deve ser inserida no README.md, na seção "Como Usar", pois esta aplicação já deve
estar consumindo remotamente a API criada na disciplina de Java para que os testes possam ser realizados.

4. LINK DO GITHUB
A EQUIPE criar um repositório no GITHUB. A URL aqui criada deve ser inserida no README.md, na seção "Como Usar”, para que a correção possa ser efetuada.
O versionamento deve estar presente no projeto. É obrigatório utilizar o GIT/GITHUB/GITFLOW para realizar o versionamento, todos os integrantes devem participar do
trabalho, sendo possível ver esta participação através do histórico de commits, por isso o mínimo de commit por integrante é 5 e o mínimo total de commits do projeto é 15.
5. GRAVAÇÃO DE VÍDEO
A equipe deve publicar um vídeo de apresentação do projeto no YouTube, de no máximo TRÊS minutos, demonstrando o funcionamento da aplicação, suas principais
funcionalidades, tecnologias utilizadas e a integração com a API. A URL do vídeo deve ser inserida no arquivo README.md, na seção "Como Usar”, para fins de avaliação.
5. APPLICATION PROGRAMMING INTERFACE (API) – JAVA – Obrigatória
A API, desenvolvida na disciplina de Domain Drive Design Using Java, será responsável por enviar e receber dados entre o backend e o frontend. Ela trará todos os dados
coletados no backend para o frontend, possibilitando também o envio de dados do frontend para o backend, viabilizando seu armazenamento no banco de dados, conforme
abordado na disciplina de Building Relational Database. Lembrando que tanto o front-end quanto o back-end devem estar publicados na nuvem.
